1 Quick start

The whole flow takes a few minutes. If you only read one section, read this one. Every step is explained in detail later in the guide.

  1. Open Dashboards and click Import floor data. Only Admin (WFM) and Manager see this button.
  2. Click Download template. You get RTM_floor_data_template.xlsx.
  3. Fill in the Roster and Agent Status sheets with your own data (Section 3).
  4. Drop the file on the dialog. The console checks it and shows a summary, or a list of what to fix (Section 4).
  5. Click Start replay. The day plays back at 60 times normal speed (Section 5).
  6. Review Dashboards and Instance Ledger (Section 7).
  7. Click Exit replay in the top bar to return to the live floor.
Try it first

The template already contains a sample day for 8 agents in 2 teams. Download it and upload it straight back to see the whole flow before preparing real data.

2 How the simulation works

The console does not load a finished day. It re-enacts your day from the first row to the last, in fast-forward, and works out the escalations as it goes.

Two ways the console can run without a live feed

ModeWhere the data comes fromUse it for
Built-in simulatorInvented by the app: 199 made-up agents in 10 teams.Demos and trying the screens. Development builds only.
Imported replayAn Excel file you fill in with a real or planned day.Seeing what the console would have done on your floor. This guide.

Why it replays instead of loading

Your file records what agents did: "Joshua went into ACW at 10:14:05", "Joshua went Available at 10:17:40". It does not record what the console should have done about it. That part is worked out by the rules engine, and the engine only works by watching time pass.

What happens every simulated second

  1. The timers advance. The engine keeps a shift clock and, for each agent, how long they have been in their current status.
  2. Events are applied. Any status change, hold or queue update stamped at that second takes effect. A status change resets that agent's timer to zero.
  3. Every rule is checked. For example, when Joshua's ACW timer reaches 120 seconds, the Extended ACW rule fires.

A rule firing is called a call-out. Each one counts a strike for that agent and that rule, and the strike number decides who is told (Section 6). Nudges, strikes, incidents and the ledger are all produced this way. None of them are in your file.

A faithful preview

This is exactly what the console will do with the live feed. The replay swaps the live feed for your recorded day and runs the clock faster, using the rules as they are currently set on the Rules Engine screen.

3 Filling in the template

The workbook has four data sheets. Two are required. The other two are optional, and each one switches on more of the console.

SheetWhat it switches on
RosterREQUIREDThe agent grid, the Team Lead, Manager and Agent views, and My View.
Agent StatusREQUIREDState timers, strikes, nudges, incidents, and the Short call and Transfer rate rules.
HoldsOPTIONALThe Long hold rule.
Queue IntervalsOPTIONALThe four queue tiles on the Console, and the Queue backlog, Service level and Abandon rate rules.

The workbook also has an Instructions sheet and a Lists sheet that feeds the Status dropdown. Leave both as they are.

Keep the structure

Do not rename the sheets or change the header row. Column order does not matter, and extra columns are ignored, but the sheet names and header text are how the console finds your data.

Roster

One row per agent on shift. This sheet decides who appears on the grid and who can see whom.

ColumnWhat to enter
Agent NameREQUIREDMust be unique, and must match the name used on the other sheets exactly, including spelling and spacing.
TeamREQUIREDThe agent's team. A team has exactly one team lead and one manager.
Team LeadREQUIREDSets the Team Lead view: this person sees only this team.
ManagerREQUIREDSets the Manager view: this person sees every team listed under them.
LOBOPTIONALLine of business, shown in the team filter. Defaults to the team name.
Adherence %OPTIONALAdherence at the start of the day, 0 to 100. Defaults to 96.

Agent Status

One row every time an agent's status changes. A status lasts until that agent's next row. Rows do not need to be sorted; the console orders them by time.

ColumnWhat to enter
Agent NameREQUIREDAn agent from the Roster sheet.
StatusREQUIREDPick from the dropdown: On Call, Available, ACW, Aux Break, Aux Personal, Outbound, Offline. Genesys names such as "On Queue", "After Call Work", "Meal" and "Break" are recognised too.
Start TimeREQUIREDWhen the status began, as a date and time, for example 2026-10-01 08:00:00.
TransferredOPTIONALY on the row that ends a call (the first status after On Call) if that call was transferred.
How a call is counted

A call is counted when an agent leaves On Call. The time they spent in On Call is the call length. That feeds the call count, average handle time and the Short call rule.

Holds OPTIONAL

One row per hold: Agent Name, Hold Start, Hold End. A hold only counts while that agent is On Call.

Queue Intervals OPTIONAL

One row per interval for the floor as a whole. Each row's values stay in effect until the next row.

ColumnWhat to enter
Interval StartStart of the interval. Required if you use this sheet.
Calls WaitingCalls in queue. A Genesys interval export does not include this; without it the Queue backlog rule cannot fire.
Service Level %0 to 100, or 0 to 1 as Genesys exports it.
ASA (s)Average speed of answer, in seconds.
Abandon %0 to 100, or 0 to 1.
Using a Genesys export

You can paste the all-queues total rows from a Genesys queue performance export straight into this sheet. Use the totals rows only, not the per-queue rows.

Before you upload

  • Every agent on Agent Status is on the Roster, spelled the same way.
  • Each team has one team lead and one manager on every row.
  • Everyone who was working at the start has a row at the start time. Agents are Offline until their first row (Section 5).
  • Start Time cells hold a date and a time, not text such as "morning".
  • The file covers one shift, saved as .xlsx and under 10 MB.

4 Uploading and checking the file

The file is checked before anything starts. You always see the result of the check first, and nothing runs until you click Start replay.

ResultWhat you seeWhat to do
PassedA teal summary line: agents, teams, status changes, holds, queue intervals and the time range.Check the numbers look right, then click Start replay.
WarningsAmber lines under the summary.Read them. The replay still runs, but something may not behave as you expect.
ErrorsRed lines, with row numbers. Start replay stays disabled.Fix the file in Excel and drop it again. All problems are listed together, so one round is usually enough.

Every message is explained in Section 8.

Uploading a raw Gencloud CSV instead

The same dialog accepts a Genesys agent-status export as .csv. It asks you to confirm which column is the agent, status and start time, and how each status maps to a console state. A CSV carries statuses only: teams get placeholder leaders, and there are no holds or queue numbers. Use the template when you want the role views and queue rules to be real.

5 How time works

Nothing about the start time is fixed. The replay takes its timing entirely from the Start Time column on the Agent Status sheet.

How it is decidedExample
Start30 seconds before the earliest status row.First row at 06:30:00, so the replay starts at 06:29:30.
End10 minutes after the last status row.Last row at 17:05:00, so it ends at 17:15:00.
Shift clockShows the time of day from your file.A row stamped 14:05:00 happens when the clock reads 14:05:00.
Speed60 times normal: one real second plays one minute of the shift.One hour of shift takes one minute.

Agents start Offline

Every agent is Offline until their first status row. If the file starts at 08:00 and an agent's first row is at 09:00, they sit Offline for that hour and can trigger the Prolonged offline rule.

If people were already working when the file starts, give each of them a row at the start time.

Good to know

  • Times are used exactly as typed. There is no timezone conversion. Whatever the cell says is what the clock shows.
  • One file is one shift. A file spanning more than about a day and a half is rejected.
  • Night shifts that cross midnight work, as long as the rows carry real dates. The clock keeps counting past 24:00, so 1:30 am on the second day reads 25:30:00.
  • Holds and Queue Intervals use the same clock. A queue row stamped before the first status row simply applies from the start.
  • You do not have to watch. Leave the tab open and come back; the result stays on screen after "Replay complete".

How escalation climbs

Strikes are counted per agent, per rule, for the shift. The same agent breaking the same rule again moves one step up the ladder:

  • Once per episode. A timer rule fires once each time the agent enters that status and overstays. Staying longer does not add strikes. Leaving, coming back and overstaying again is a new strike.
  • One incident per agent per rule. The third strike opens an incident numbered INC-2026-NNNN. Later strikes on the same rule raise that incident's count instead of opening another.
  • Rules that start with the Team Lead skip the nudge: strikes 1 and 2 go to the Team Lead, strike 3 to Ops.
  • Adherence breach and Transfer rate fire once per shift and do not repeat.
  • Queue rules are not about one agent. They are logged against "Queue", fire once per breach, can fire again after the number recovers, and never open incidents.
Adherence is modelled, not imported

Adherence starts at the Roster value, falls slowly while an agent is in Aux Personal or Offline, and recovers slowly while On Call. Real adherence will come from NiceIEX once the live feed is connected.

7 Reading the result

While a replay runs, the top bar shows a purple "Data replay" pill and the shift clock runs through your day. Move between screens at any time; each one shows the day up to the point the replay has reached.

ScreenWhat it shows
ConsoleThe agent grid with statuses and timers, cards glowing amber or red while in breach, and the trigger feed of the latest 40 call-outs.
DashboardsTotals by stage, call-outs by rule and by agent, the investigation register and a team breakdown. The best end-of-day summary.
Instance LedgerEvery call-out in order. Can be exported to CSV.
Rules EngineThe thresholds the replay is using.
My ViewSwitch View as to Agent and pick someone to see the day from their side.

What is different from a live floor

  • No pop-ups. Nudges and call-out toasts are switched off during a replay so you are not flooded. They are still recorded in the trigger feed and the ledger.
  • Only you see it. The replay belongs to your session. Everyone else keeps seeing the live floor, and so do you once you click Exit replay.
  • You can still act on it. Acknowledging call-outs and working incidents works inside a replay, which is useful for training. It is all discarded when you exit.
  • Role views follow your file. The people in the View as selector become the team leads, managers and agents from your Roster.
  • Queue tiles show your numbers, or a dash if the file has no Queue Intervals sheet.
Export before you exit

A replay is not saved. When you click Exit replay the results are gone. If you need to keep them, use Export CSV on the Instance Ledger and Export incidents CSV on Dashboards first.

9 Limits

  • It is a preview, not a record. Results are held for your session only and are discarded when you exit the replay or the server restarts.
  • One shift per file, up to 10 MB, in .xlsx format.
  • The speed is fixed at 60 times. There is no pause, skip or instant mode yet.
  • Statuses come from your file, not from Gencloud. The result is only as accurate as the rows you enter.
  • Adherence is estimated from time in status, not imported per interval.
  • The built-in simulator (the made-up floor) runs in development builds only. A production build with no live feed shows an empty floor until you import a file.
Handle real exports with care

Genesys exports contain internal queue names and identifiers. Keep working files on your own drive or the team's shared drive. Do not email them outside the team or add them to the code repository.

10 Frequently asked questions

Why does a nine-hour shift take nine minutes?

The console replays the day second by second at 60 times normal speed, so one hour of shift takes one minute. It has to walk through the day because escalations depend on how long each status lasted (Section 2).

Does every file start at 08:00?

No. The replay starts 30 seconds before your earliest status row, whatever time that is. 08:00 is only what the sample data uses.

Will other people see my replay?

No. It is private to your session. The live floor keeps running for everyone else.

Can I pause, skip ahead or change the speed?

Not yet. The speed is fixed at 60 times. You can leave the tab open and come back when it finishes.

Half my agents are showing as breaching Prolonged offline. Why?

They had no status row near the start of the file, so they were Offline until their first row. Add a row for each of them at the start time.

I changed a threshold. Do I need to upload again?

Yes. A threshold change applies from that moment on, so earlier parts of a running replay used the old value. Exit the replay and start it again for a clean result.

Can I use our real Genesys export directly?

An agent-status export can be uploaded as a CSV (Section 4). A queue performance export has no agents in it, so it can only fill the Queue Intervals sheet of the template.

The Team Lead and Manager names in "View as" changed. Is that right?

Yes. During a replay the selector lists the people from your Roster sheet, so you can check each person's view of the day.

Who do I contact if the upload keeps failing?

The BITS Automation Team. Send the file and the messages shown in the dialog.
