# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A third floor source, "demo": the real Genesys structure of every cached org with invented people, a pre-filled ~3-hour shift, and presenter keys that walk one agent through nudge → team lead → operations.

**Architecture:** `SimFeed` learns to run a given floor (explicit uids, queue membership, reporting lines), a `kind` of `"demo"`, no outage, and a `cue()` that pins one agent into a backdated state. `lib/feed/demoSeed.ts` turns cached rosters into that floor with invented names. `lib/server/runtime.ts` gains `createDemo()` (cloned rules, no recorder, no desktop push, warm-up in background chunks) and a cue API; snapshot, routes and client learn the `"demo"` source.

**Tech Stack:** Next.js 16 route handlers, TypeScript, zustand, vitest.

**Spec:** `docs/superpowers/specs/2026-11-19-demo-mode-design.md`

## Global Constraints

- No real person's name or Genesys uid anywhere on the demo floor. Demo uids: agents `demo:<n>`, leaders `demo:lead:<n>`.
- Nothing from the demo runtime reaches `store()` (no recorder, no `ruleChanged`/`overrideChanged`, no push). `feedSwitched` is still logged.
- Status label while on demo: `Demo floor`; while warming: `Demo floor · preparing the shift…`.
- Cue rule: `ovbrk` (Overbreak). Keys `1`/`2`/`3` fire the cue agent's next strike (no-op at 3); `0` picks a fresh cue agent.
- Warm-up target: 3 h of floor time (shift opens 08:00, demo opens ≈ 11:00), run in chunks of ≤ 20 ticks with `setImmediate` between, `S.quiet = true`, `S.agentsLoading = true` until done.
- Names deterministic from a fixed seed (same floor on every switch).

## Review Focus

1. **Switching away mid-warm-up** — the background warm must stop when the demo runtime is stopped; test via `stop()` during warm (Task 3).
2. **Org with no cached roster** — left out; no roster at all → simulator's sample structure (Task 1 test `falls back to null when nothing is cached`).
3. **Presenter keys while typing** (rule threshold input, reason box) — the shortcut ignores events from inputs/textareas (Task 5).
4. **Cue pressed on a non-demo floor** — `/api/demo/cue` returns 409 (Task 4).
5. **Re-firing the same rule** — strike 2 must fire even though the agent was already over the limit; cue forces a state change first (Task 2 test `cue re-arms the rule`).
